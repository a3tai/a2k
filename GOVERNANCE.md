# Governance

A2K uses maintainer-led public RFC governance during the `v0.x` series.

## Roles

- **Contributors** may open issues, discussions, and pull requests.
- **Reviewers** provide technical or domain review but do not gain merge authority by review alone.
- **Maintainers** accept RFCs, merge changes, publish releases, and handle security reports.

The initial maintainer set is the GitHub team with maintain permission on `a3tai/a2k`. A named public roster will be added before the first release.

## Normative changes

A normative change requires:

1. a public RFC pull request;
2. an announced review window;
3. recorded disposition of material objections;
4. maintainer acceptance;
5. corresponding schema, fixture, and compatibility updates where applicable.

Maintainers decide during `v0.x`. Decisions must be documented; silence is not consensus. Accepted normative releases are not rewritten silently—errata and successor releases preserve history.

## Security changes

Embargoed vulnerability fixes may bypass public RFC review until disclosure is safe. They still require maintainer review and a retrospective record when disclosure would not increase risk.

## Independence

A2K is stewarded by A3T. It must not claim independent standards-body status or certification until governance and conformance are demonstrably independent.
